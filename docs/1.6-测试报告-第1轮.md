| D-01 | TC-DSP-11 | **整数通路上软件音量完全失效，且信号路径谎报"已衰减 -6.0 dB"** | `int_pipeline=True` + `dsp_bypass=False` + `volume_mode=software` + `volume_db=-6`，播 1 kHz 正弦，实测 RMS 比 = **1.000**（应 0.501）；同一 `snapshot()` 里 gain 级却是 `CHANGED / -6.0 dB 浮点乘法` | `decoder._pick_sample_fmt()` 只判 `int_pipeline/bit_perfect`，不判音量/EQ；`engine._make_output()` 在 `ring.dtype != float32` 时传 `hook=None` → DSP 从未执行；`_refresh_signal()` 仍按 `dsp.snapshot().gain_active` 标 CHANGED（声明独立于事实） | ① 判整数通路前先判「DSP 是否真会改样本」（音量非 0 / EQ 开 / 非旁路），互斥时降级 f32；② 或让 `DspChain.process` 首行拒绝非 float32 缓冲 | **已通过**：最终收敛为唯一裁决点 `dsp.int_pipeline_allowed(settings, volume_db)`（dsp.py:67），解码器与引擎共用；`DspChain.process()` 另加 `buf.dtype != float32 → return False` 护栏。实测 `ip=True + software -6dB` → RMS **0.03034 / 基线 0.06053 = 0.5013**，格式级显示 `f32` 并带 `整数通路不可用（DSP 已启用，改用浮点）`；纯直通 `ip=True` 仍走 `s16`。详见 §7 |
| D-02 | TC-ENG-10 | **把进度条拖到最右端（曲末）会进入 ERROR，提示"解码器没有产出任何音频，可能是不支持的格式"** | 1.2 s 曲目，`engine.seek(10**9)` → 返回 `False`、`state=ERROR`；`seek(1199)` 同样。连续 5 次复现 5 次 | `_start_item()` 把"解码器 0 帧"一律当致命错误：`if not prefilled and not alive and ring.available == 0: _fail("没有产出任何音频…")`。落在末尾 1 ms 时 ffmpeg 合法地不产出任何帧 | 区分「解码失败」与「落点在曲末」：0 帧且 `returncode in (0, None)` → 按曲末处理（IDLE + EOF 事件 + 清空错误），只有非 0 退出码才 ERROR | **已通过**：engine.py:816-824 已按此实现。复验 `seek(1e9)` → `True`，停在 1080 ms，`error=""`，无 ERROR |
