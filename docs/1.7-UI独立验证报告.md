## 五之二、`test_mini_boundary_operations` "卡死" 根因（已查清，测试自身问题，已修）

### 现象
工程师报告该文件纳入 discover 后卡在 `test_mini_boundary_operations`；我这边全文件跑也曾卡在该用例（另一次卡在 `test_lyrics_read_same_panel` 的 `setUp`）。**但单跑该用例 6.5 s 必过**，打点显示 ffmpeg 合成 1 s、probe 1 s、`pump(3.5)` 3.5 s，没有任何源码死锁。

### 定位方法
在文件顶层加 `faulthandler.dump_traceback_later(60, repeat=True)`，全文件跑到卡住时拿到栈：

```
Timeout (0:01:00)!
Thread 0x00004fa4 (most recent call first):
  File "src/seqaudio/ui/main_window.py", line 2917 in apply_theme
  File "src/seqaudio/ui/main_window.py", line 158 in __init__
  File "tests/test_ui_modes_independent.py", line 112 in setUp
```

### 结论
**不是 ffmpeg、不是删除护栏、不是迷你条源码死锁。** 是 team-lead 已说明的本机已知环境问题：
`MainWindow.apply_theme → setStyleSheet` 在**同一进程反复构造多个 MainWindow**（本文件 setUp 每条用例都新建一个）时会卡住，`main_window.py:2917`。单跑一条只构造一次，所以不现；全文件第 7~11 次构造必现，看起来像"卡在某个测试"。

### 自修
在 `BaseWindowTest.setUp` 里 `mock.patch.object(MainWindow, "apply_theme", autospec=True)`，只跳过窗口**构造时**的主题应用；在 `test_theme_and_i18n_follow` 里显式调用保存的原函数一次，保留"主题切换后迷你条配色跟随"的真实验证。删除护栏的 `paths._writable` mock 同样保留。

### 复验
`QT_QPA_PLATFORM=offscreen python tests/test_ui_modes_independent.py -v` →
**Ran 17 tests in 246.122 s / OK**，其中：
- `test_mini_boundary_operations`：打点 `synth@00:00:06 → probe@00:00:07 → enqueue/play@00:00:07 → mini next@00:00:07 → pump done@00:00:11 → ok`
- `test_theme_and_i18n_follow`：**ok**（QA-UI-01 已由 `baa2933` 修好，8 语言全过）
