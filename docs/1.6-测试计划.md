### 0.3 三个最可能出问题的场景（测试资源优先压这里）

| 排序 | 场景 | 为什么危险 | 一旦出错的形态 | 重点用例 |

| 2 | **默认后端 `wasapi` → `mme` 的三处同步** | 源码默认值（`config.py:112`）、设置面板下拉选中项、单测 `EXPECTED_DEFAULTS`。三处任一漏改，就出现"面板显示 mme、实际走 wasapi"或"单测假红挡住真 bug" | 配置生效路径分裂；测试红灯误判成源码 bug，白烧一轮 | TC-GUI-20、TC-SES-05、TC-OUT-01（现有 `test_settings_defaults`） |

### 1.1 四层结构

| 层 | 范围 | 执行方式 | 频率 | 拦截目标 |
|---|---|---|---|---|

### 1.2 策略要点

1. **优先级按"保底 18 项 + 静默错误"排**，不按代码行数排。凡属"用户听得出但看不出"的缺陷（变调、声道错、削波）一律 P0。
2. **能合成就不依赖素材**：采样率矩阵、格式矩阵、损坏样本全部用内置 ffmpeg 现场生成，避免用例绑定某台机器上的音乐文件。**例外**：APE、DFF、AIFF/CAF/AU 本机 ffmpeg 无对应**编码器**（只能解码），必须用真实样本或按第八节豁免。
3. **异常路径与正常路径同权重**：设备忙、设备拔、0 字节、索引坏、版本不识别——这些是"上线才发现"的高发区。
4. **判定标准必须是数字**：`underruns == 0`、`|帧数差| ≤ 1 块`、`|gap| ≤ 20 ms`、`seek 误差 ≤ 50 ms`、`RSS 增长 ≤ 5 MB/h`。禁止"播放正常"这类不可判定描述。
5. **两轮上限**：一轮写完跑；失败按"源码 bug → 工程师 / 用例 bug → 自修"分流；第二轮仍红则记入"已知问题"不再追（避免拖期）。

## 五、缺陷分级与发布门槛

### 5.1 分级

| 级别 | 定义 | 典型例子 | 处置 |
|---|---|---|---|
| **P0 阻断**（不能发版） | 保底 18 项任一不达标；崩溃；数据损坏；**静默变调/变速**；静默声道错误；写入用户文件出错 | WASAPI 回退后解码侧仍按 44.1k 出 PCM（变调）；双击播不出来也编不了标签；播放中写坏标签；`-acodec f32le` 导致全程静音 | 立即修，修完重跑 L1–L3 |

### 5.2 发布底线（6 条，缺一不发）

### 5.3 一票否决清单（看到即 P0）

1. 播放中把 PCM 按错误采样率送进设备（听感变调/变速），且界面无任何标注。
2. `-acodec` / `-f` 参数拼错导致"打开成功但全程静音"。
3. 播放触发任何标签写盘（`playback_writeback_tags` 默认为关，若被打开须走三层保护 + 二次确认）。
4. 界面/日志出现 `bit-perfect` / "逐样本一致" / "位完美已验证"（违反 R2 措辞铁律）。
5. 退出时未 `engine.shutdown()` 导致下次启动设备被占、或进程残留。
6. `player/` 包 import 了 PySide6（破坏可测性与线程边界）。

## 八、已知限制与豁免（**不记缺陷**）

| # | 限制 | 影响 | 处理方式（本计划的判定口径） |
|---|---|---|---|
| L1 | **WASAPI 共享模式本机仅接受 48000** | 44.1k/88.2k/96k/176.4k/192k 源全部回退重采样 | 这是**已知且如实标注**的行为。判定标准是"回退后不变调、界面标 `CHANGED`、计数器 +1"，**不是**"必须按源率出声"。回退本身不记 bug；**回退后变调记 P0** |
| L2 | **内置 ffmpeg 无 `ape` / `aiff` 编码器，无 `dsf`/`dsdiff`/`iff` 复用器** | APE、AIFF/CAF/AU、DSF/DFF **无法合成**，只能靠真实样本 | 有真实样本：APE 2 处（已定位）；DSF 50 个（已定位）。**无真实样本：DFF、AIFF/CAF/AU → 豁免**，在发版说明写明"未实测"，不得写"支持" |
| L3 | **本 build 未检出 `mpc`(Musepack) 解码器、`dca`(DTS) 未单独验证** | FR-DEC-005 列出的 MPC / DTS 核心无法实测 | MPC 豁免；DTS 按"AC-3/E-AC-3 已验证"部分覆盖，MPC/DTS 在 README 格式表标注"未实测" |
| L4 | **无 ASIO** | "独占"只有 WASAPI 一条路径可验；WDM-KS 属实验后端 | 不测 ASIO；WDM-KS 只验"能出声 + 不崩"，**不承诺位完美** |
| L5 | **位完美无法客观证明**（需回环录音硬件） | 只能以"设备端读数 + 内部计数器 + 全 PASSTHROUGH 状态"为证 | 判定口径固定为"界面文案 = 未做软件改动"；**禁止**任何"已验证/逐样本一致"表述 |
| L6 | **CUE 整轨 seek 精度 ≤50 ms**（不是样本精确） | APE 等需重建索引的格式可能有若干毫秒偏差 | 验收线 = 50 ms；<50 ms 的偏差不记缺陷，>50 ms 记 P1 |
| L7 | **DSD 只做 →PCM，默认 176.4 kHz**；DSD256 seek 精度不承诺 | 高规格 DSD 的 seek 与 CPU 指标受限 | CPU ≤25% 只对 DSD64/128 承诺；DSD256 只记录；DSD 窗口内 seek 精度不判红 |
| L8 | **逐字 LRC 降级为逐行** | 逐字增强型 LRC 不逐字高亮 | 按决策执行：能显示即达标（TC-GUI-14），**不记缺陷** |
| L9 | **批处理期允许已播曲目继续** | 与 R8 的"严格禁止"不同 | 按主理人决策：禁止**起播**、允许**继续播**。暂停已播曲目反而算过度打断 |
| L10 | **热插拔后不自动恢复播放**（v1.6.1） | 需手动点"重新连接" | TC-OUT-15 判定"手动可续播"即达标；**不要求自动** |
| L11 | 会话恢复时曲库根盘符缺失 | 队列项不可用 | 按 Q6 决策：灰显保留、跳过、不自动删；**不记缺陷** |
| L12 | `test_ui_flow.py` 是脚本不是 unittest | `TestLoader` 计数为 0，无法用 `pytest --count` 统计 | CI 必须按**退出码**判定；本计划的"266 项"只统计 unittest 两个文件 |
| L13 | 无 `psutil` 依赖 | 内存/CPU 采样受限 | TC-PERF-03 用 `ctypes` 采 `PROCESS_MEMORY_COUNTERS`，或手工读任务管理器；TC-PERF-04/05 归手工 |
