| # | 场景 | 通过标准 | 实测（本机 2026-11） |
|---|---|---|---|
| **E1** | 44.1k FLAC + WASAPI 独占 | 有声、`stream.samplerate=44100`、信号路径 `output` 级显示「独占」 | ✅ `--audio-smoke --mode=exclusive`：`exclusive=true`、`rate=44100`、`output_mode=exclusive`、`system_mix_rate=48000`、`underruns=0`、`wording=L1` |

| **E3** | 独占时打开浏览器播视频 | 浏览器无声（预期），状态栏/播放条有「独占」标识；关掉播放后恢复 | ⬜ 人工项（自动化不可判定）——依赖 T04 的「独占」徽标；`snapshot()["exclusive"]` 已可供 UI 判定 |

## 三、ASIO 决策记录（设计 §5.2 第 4 条）

- **v1.7 不纳入 ASIO 的实际启用**，只做「能力可见 + 明确不可用」。
- 现状：`build.py` 打包后只保留 `libportaudio64bit.dll`，ASIO 变体（`libportaudio64bit-asio.dll`）被清理，
  并由 `build_onedir()` 的断言锁住（目录里出现 `*-asio.dll` 直接 `SystemExit`）。
- 设置面板：ASIO 项**置灰** + 提示「当前 PortAudio 构建不含 ASIO；本版未启用」。
- 决策理由（沿用 v1.6 结论）：① 替换 DLL 会让 ASIO 成为唯一 PortAudio，所有后端风险面 100%；
  ② 本机无 ASIO 驱动，无法验收它对 WASAPI 的副作用；③ ASIO SDK 再分发许可未确认。

### v1.7.1 若要上 ASIO，前置条件（缺一不可）

- [ ] 法务确认 ASIO SDK 再分发边界（或明确"仅随 sounddevice 官方 wheel 分发"）；
- [ ] 在**有 ASIO 驱动**（DAC 或 ASIO4ALL）的机器上跑完：真开流、48k/96k、与其他后端回归、拔插恢复；
- [ ] 解决音量语义：ASIO 下设备音量由驱动控制，软件音量仍有效但用户会误以为在调硬件；
- [ ] 解决与 WASAPI 独占的**互斥**：同一时刻只允许一个后端持有设备。
