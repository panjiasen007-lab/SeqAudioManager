### 3.1 ① 降级兜底：实测发现**两级**，都已验证

**第一级（本机真实发生）**：探测假阳性 → **保住独占、换采样率重试**。dev18 的 44.1k 独占：探测 ✓、开流 `-9996`。

```
第1级 44100 exclusive  → FAIL -9996
第2级 88200 exclusive  →（换率重试）
最终 48000 exclusive   → OK，exclusive=true，mode_note="探测通过但开流被拒（已记录），实际改用 48000 Hz"
```
判定：`state=PLAYING`、`exclusive=True`、`output_mode=exclusive`、output 级 **FALLBACK**、`_spec.sample_rate == snapshot["rate"] == 48000`（**不变调**）、`underruns=0`。

**第二级（mock 制造"独占彻底不可用"）**：退回共享。

```
第1级 44100 exclusive → FAIL → 第2级 88200 exclusive → FAIL → 第3级 48000 shared → OK
结果：exclusive=false、output_mode=shared、output_mode_requested=exclusive、output 级 FALLBACK、出声
```

**缓存粘滞（第二次起播）**：实测 prepare 调用序列

| 起播次序 | prepare 调用 | 起播耗时 |
|---|---|---|
| 第 1 次 | `(44100, exclusive) → (88200, exclusive) → (48000, shared)` | 349 ms |
| 第 2 次 | `(48000, shared)` —— **一步到位** | 238 ms |
| 第 3 次 | `(48000, shared)` | 208 ms |

即"探测说行但开流被拒"的结论会被记住，不会每次起播都重演两次失败。

## 九、skip 集键维度（本轮核心新增）

### 9.1 这是什么

引擎为避免"每次起播都重演两次失败开流"，会记住某台设备上**哪一级回退失败过**并在下次跳过（`_device_skip_levels`）。这个缓存是**性能优化**，但它一旦键不够细，就会把"某首歌的失败"错误地推广到"所有歌"——表现为**本来能跑独占的文件被降级**。

### 9.2 修复前实测（缺陷确认）

固定设备 dev18（Nahimic），同一引擎实例，先播 44.1k 再播 48k：

| 次序 | 请求 | 实际结果 | skip 集 |
|---|---|---|---|
| 第 1 次 | 44.1k exclusive | level 1 失败（探测假阳性 -9996）→ 降级 **48000 exclusive 成功**；`exclusive=True` | `{16: [1]}` |
| 第 2 次 | **48k exclusive** | **`exclusive=False` / `output_mode=shared` / output 级 FALLBACK**；日志出现"实际改用 44100 Hz（exclusive）" | 未变 |

判定：48k 独占本身是探测通过的（`supports_rate(dev18, 48000, 2, "exclusive") == True`），只因 **level 1 被按设备整体跳过**，才被拖到 level 3（44100）→ 再失败 → 退回共享。**这是 P1：用户切歌（44.1k→48k）就丢独占，且面板只显示"共享"，看不出是缓存污染。**

### 9.3 修复后的验收口径（三条必须同时成立）

| # | 断言 | 说明 |
|---|---|---|
| A | **同设备、不同采样率互不污染**：44.1k 层级 1 失败后，48k 仍能拿到真独占，`rate=48000`、output 级 **PASSTHROUGH**、`fallback=False` | 由 `test_7_skip_set_keyed_by_rate_and_mode` 断言（当前 **红**） |
| B | **同设备、同率、同模式仍能跳过**：第二次播 44.1k 只做 1 次 prepare 尝试 | 由 `test_7b_skip_set_still_skips_same_triple` 断言（当前 **绿**，修完不能退化） |
| C | **换模式不串味**：exclusive 的失败不应影响 strict（反之亦然） | 三维键自然覆盖，随 A/B 一起回归 |

### 9.4 状态
