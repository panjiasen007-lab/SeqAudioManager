# v1.6 需求范围（播放能力）

> 上游输入：`全格式音乐播放器产品需求文档V1.0.docx`（项目代号 Resonance，48 条 P0 / 32 条 P1 / 12 条 P2）。
> 本文把它裁剪为「在既有 Windows 元数据工具上加播放内核与播放界面」的可交付范围。
> 基线核对对象：`README.md`、`spec.md`、`docs/GAP.md`、`src/seqaudio/`（v1.5.8，Python 3.13 + PySide6 6.12）。

## 零、结论摘要

| 指标 | 数量 |
|---|---|
| PRD P0 条目总数 | 48 |
| 已具备（现有功能已满足） | 10 |
| 本期实现 | 13 |
| 本期部分（实现子集，差异写明） | 20 |
| 不在本期（v1.7 及以后 / 永久不做） | 5 |
| 本期实际动工条目 | 33（保底 18 + 弹性 15） |

一句话定位：**v1.6 只做「能播、播得准（可控可查）、能从现有曲库直接播」，不做播放器产品化。**

技术路径（唯一一条，不做分叉）：`ffmpeg 7.1 子进程解码`（复用已内置的 imageio-ffmpeg）→ 原始 PCM 管道 → numpy 环形缓冲 → `sounddevice 0.5.6 / PortAudio` 输出（WASAPI 独占可选）。
已实测：`sounddevice 0.5.6` 可用，本机 34 个设备，PortAudio 提供 MME / DirectSound / WASAPI / WDM-KS 四套后端（**无 ASIO**）；`WasapiSettings(exclusive=True)` 可构造；内置 `ffmpeg 7.1` 含 `dsd_lsbf/dsd_msbf`、`ape`、`wavpack`、`tta`、`alac`、`truehd` 等解码器。

## 一、版本定位

### 1.1 是什么

| 维度 | v1.6 |
|---|---|
| 形态 | 现有「音序管家」新增播放能力，**同一个 EXE**、同一套主题与 i18n、同一份便携 data 目录 |
| 曲库 | 直接复用当前扫描出的内存曲目表（含 CUE/SACD ISO 展开的多轨行），不引入新数据库 |
| 播放范围 | 单一队列、顺序/随机/循环、无缝（同规格）、淡变、防爆音、会话恢复 |
| 输出 | WASAPI（共享 + 独占）为默认，DirectSound/MME/WDM-KS 可选；采样率跟随；软件音量与 0 dB 旁路 |
| 可信度呈现 | 新增「信号路径」面板：逐级显示 源格式 → 解码器 → 样本格式 → 音量/EQ → 输出后端 → 设备上报格式，并给出重采样/增益/underrun 计数器 |
| 平台 | 仅 Windows 10 1809+ / 11（与现有产品一致），macOS/Linux 不做 |

### 1.2 不是什么（明确不承诺）

| 不做 | 原因 |
|---|---|
| 不做 foobar2000 / JRiver 级播放器 | PRD 是完整产品级规格（31 周、6 人）；v1.6 是单人 1~2 周的增量版本 |
| 不做资源库重构（SQLite / FTS5 / 指纹） | 现无数据库，全量重建扫描足够；引入持久库是独立版本的工作量 |
| 不做远程控制、DLNA、Subsonic、流输出 | 全部 P1/P2，且与「本地元数据工具」主线无关；v1.6 不监听任何端口 |
| 不做插件体系（C ABI） | Python 实现无法保证实时线程纪律与进程隔离；需要另立需求 |
| 不做 Native DSD / DoP | Native 仅 ASIO 或系统原生路径，ASIO 不在 pip 轮子且 SDK 不许随包分发 |
| 不做位完美的实验室级证明 | 回环录音比特比对依赖外部录音硬件，无法进入自动化验收 |
| 不宣称「HI-RES 播放器」营销定位 | 播放是既有工具的延伸能力，不是新产品的卖点重写 |

## 二、P0 达成矩阵

状态口径：`已具备` = 现有代码已满足，本期只做衔接；`本期实现` = 按 PRD 原意完整实现；`本期部分` = 实现可验收的子集，差异逐条写明；`不在本期` = 不进 v1.6 排期。

### 2.1 解码引擎（FR-DEC）

| 编号 | PRD P0 要点 | v1.6 状态 | 落地方式 / 理由 |
|---|---|---|---|
| FR-DEC-001 | 无损与无损压缩：FLAC 32/384、ALAC、APE、WavPack、TTA、TAK、Shorten、WAV、AIFF、CAF、AU | 本期实现 | ffmpeg 子进程解码为原始 PCM；格式白名单沿用 `core/model.py` 的 `LOSSLESS_EXTS`（11 个扩展名），参数取自 `core/probe.py` 的 `AudioInfo`。不引入专用解码库 |
| FR-DEC-002 | DSF/DFF，DSD64–512，多声道，ID3/DIIN | 本期部分 | 用 ffmpeg `dsd_lsbf/msbf` 解码为 PCM（默认 176.4 kHz，可选 88.2/176.4/352.8）。理由：Python 侧无 DSD 位流直通能力，Native/DoP 见 FR-OUT-006 |
| FR-DEC-003 | SACD ISO 盘结构、立体声/多声道区、DST、按轨定位 | 不在本期（v1.7） | `core/sacd.py` 目前只解析曲目表 + 调 `sacd_extract` 落盘 DSF；实时播放需流式解 DST，超出本期。v1.6 提供「先分轨为 DSF 再播放」路径 |
| FR-DEC-004 | WAV/APE/FLAC + CUE 整轨、INDEX 00/01、隐藏轨、PREGAP | 本期实现 | 复用 `core/cue.py` 的 `start_ms/end_ms` → ffmpeg `-ss/-t` 定位；`probe.expand_cue_tracks()` 已把整轨展开成多行，队列按行入队即可 |
| FR-DEC-005 | MP3(LAME/Xing)、AAC-LC/HE、Vorbis、Opus、WMA、Musepack、AC-3/E-AC-3、DTS 核心 | 本期实现 | 同上；白名单用 `LOSSY_EXTS` + `EXTRA_EXTS`。逐格式实测结果回填 README 格式表 |
| FR-DEC-006 | MKV/MKA、MP4/M4A/M4B、OGG、ASF、AVI 纯音频轨，可指定音轨、忽略视频 | 本期实现 | ffmpeg `-map 0:a:0` 显式取首音轨，视频轨天然忽略 |
| FR-DEC-008 | 解码失败按帧丢弃续播；超阈值停播并给错误摘要 | 本期部分 | ffmpeg 侧 `-err_detect ignore_err` + 管道断流检测；会话内累计错误帧/断流次数并写日志。理由：PCM 管道拿不到逐帧错误位置，无法做到 PRD 要求的「可复现错误位置摘要」 |
| FR-DEC-009 | 内部统一 32 bit 浮点；无损整数链路可走整数通路 | 本期部分 | 整数通路：按源位深直接请求 `s16le/s24le/s32le`，不经浮点；非整数通路 float32 后再转设备格式。理由：EQ/淡变/音量一旦启用必然进浮点，故「整数通路」仅覆盖音量旁路且无 DSP 插入的场景 |
| FR-DEC-011 | 专用库优先、FFmpeg 兜底；解码器与版本可查，可强制指定 | 本期部分 | 只有 ffmpeg 一条后端，如实显示「ffmpeg 7.1 · flac」并记录到日志。理由：无第二后端，「优先/兜底」与强制指定无意义，随 v1.7 多后端再补 |

### 2.2 音频输出（FR-OUT）

| 编号 | PRD P0 要点 | v1.6 状态 | 落地方式 / 理由 |
|---|---|---|---|
| FR-OUT-001 | 独占输出：WASAPI（事件/推送）、ASIO 2.2、KS | 本期部分 | `WasapiSettings(exclusive=True)` 实现 WASAPI 独占（PortAudio 用事件驱动）；设置里额外列出 WDM-KS 与共享模式。理由：ASIO 需 PortAudio 带 ASIO SDK 自行编译、SDK 许可禁止随包分发；WDM-KS 在 PortAudio 属实验后端，不承诺位完美 |
| FR-OUT-002 | 采样率自动跟随，失败回退并提示原因与建议采样率 | 本期实现 | 按源采样率开口设备；失败依次试设备默认率 → 48 k → 44.1 k，回退时信号路径标红并给出建议值与设备名 |
| FR-OUT-003 | 位完美模式下禁止重采样/位深转换/混音/软件增益，路径逐级显示 | 本期部分 | 位完美模式 = 采样率与位深强制等于源 + 音量 1.0 + 空 DSP 链，逐级标注「原样通过/已改变」。理由：回环录音比特比对（AC-02）依赖外部硬件，本版本不作为验收项，只以设备端读数 + 内部计数器为证 |
| FR-OUT-004 | 立体声、多声道 5.1/7.1 直通，声道映射/交换、单声道下混、LFE | 本期部分 | 立体声与多声道按源直通（设备支持时）；单声道/多声道下混用 ffmpeg `-ac 2`。理由：声道矩阵、交换与 LFE 提取是独立 DSP 模块，随 v1.7 |
| FR-OUT-005 | 硬件音量 / 软件 32 bit 浮点 / 固定 0 dB 三级 | 本期部分 | 软件浮点音量 + 固定 0 dB 旁路（选择旁路时音量控件置灰并提示系统音量仍可能衰减）。理由：硬件音量需 COM 调 `IAudioEndpointVolume`，本期不引入 COM 层 |
| FR-OUT-006 | DSD 三模式：Native / DoP / DSD 转 PCM | 本期部分 | 只做 DSD→PCM。理由：DoP 需按 24 bit 帧打包 0x05/0xFA 标记并逐设备验证；Native 依赖 ASIO 或驱动私有接口，二者都需真实解码器回归，放 v1.7 |
| FR-OUT-010 | USB 解码器拔出暂停并保留位置，插回自动恢复 | 本期部分 | 捕获 PortAudio 错误与设备列表变化 → 暂停 + 保留位置 + 明确提示；插回后**手动**点「重新连接」。理由：自动恢复需设备指纹匹配与重试策略，v1.6.1 |

### 2.3 DSP 链（FR-DSP）

| 编号 | PRD P0 要点 | v1.6 状态 | 落地方式 / 理由 |
|---|---|---|---|

## 六、风险

### 6.1 技术风险

| # | 风险 | 影响 | 对策 |
|---|---|---|---|
| R1 | **PortAudio 打包**：`sounddevice` 依赖 `_sounddevice_data/portaudio-binaries/libportaudio64bit.dll`，PyInstaller 默认不收集 | 打包版 ImportError，源码版正常 → 最典型的"上线才发现" | `build.py` 显式 `add-binary`；便携版与安装版各做一次冒烟（列设备 + 播 10 秒），列为发版前置检查 |
| R2 | **位完美无法客观证明** | 对外口径若写成"bit-perfect 已验证"会与实际证据不符 | 界面与文档统一措辞为「未做软件改动」，不写"逐样本一致"；AC-02 回环比对标记为「需实测，本版本不作为验收项」 |
| R3 | **WASAPI 独占的设备兼容性不可控** | 部分驱动在独占下拒绝非默认采样率（192 k）/拒绝 24 bit，导致"采样率跟随"失败；独占还会踢掉浏览器与会议软件 | 失败自动回退共享并明确提示；独占作为可选而非默认；建立"实测设备清单"文档，未知设备不承诺 |
| R4 | **Python 回调实时性**：GIL、GC、异常栈都可能造成 underrun | 播放卡顿/爆音，40 ms 缓冲下更敏感 | `RawOutputStream` + 预分配 numpy 环形缓冲 + 回调内零分配零日志；underrun 计数为验收项；必要时把缓冲下限抬到 60 ms |
| R5 | **CUE 整轨 seek 精度**：ffmpeg `-ss` 对 APE 等需重建索引，可能非样本精确 | 轨首截掉/多出若干毫秒 | 验收放宽到 ≤50 ms；「样本精确定位」标注待验证；必要时用 `-ss` 前置 `-accurate_seek` 并实测回填 |
| R6 | **DSD 转 PCM 的 CPU 与 seek**：DSD256→176.4 k 解码开销大，DSD 场景 seek 精度差 | 高规格 DSD 卡顿、定位偏差明显 | CPU 上限只对 DSD64/128 承诺（≤25%）；DSD 窗口内 seek 精度不承诺 |
| R7 | **VBR 无索引文件的时长与定位误差** | 进度条跳变、seek 落点偏移 | 以 ffprobe 时长为准；对无索引文件在面板标注「时长估算」 |

### 6.2 体验风险

| # | 风险 | 影响 | 对策 |
|---|---|---|---|
| R8 | 现有用户把工具当"处理工具"，播放条出现后被理解为功能膨胀 | 界面被抱怨变复杂；批处理时误触播放 | 播放条默认折叠/可关闭；批处理进行中禁止起播并提示；不改动现有工具栏顺序 |
| R9 | 独占输出导致其他软件无声，用户不知情 | "播放器把我会议静音了" | 首次启用独占弹一次说明（可勾不再提示）；状态栏常驻独占标识 |
| R10 | 曲库=当前列表，用户以为"重新打开就没了" | 误以为曲库丢失 | 记住曲库根并启动自动载入；首次启动在状态栏说明曲库来源 |
| R11 | 播放与批量写标签/分轨同时跑，磁盘与 CPU 争用 | 播放卡顿、写标签变慢 | 播放优先，扫描/转换任务在播放时降并发（沿用现有 `concurrency` 设置） |

### 6.3 范围风险

33 项（保底 18）对单人 1~2 周仍偏紧，瓶颈不在解码而在**界面组装**与**设备兼容实测**。若时间不足，按以下顺序砍，砍掉的项全部进入 `v1.6.1` 清单，不算违约：

1. FR-DSP-003 EQ（10 段）
2. FR-PL-004 交叉淡变
3. FR-TOOL-001 频谱补齐
4. FR-UI-002 迷你条 + 托盘
5. FR-DEC-002 DSD 播放

保底档的底线是：**FLAC/WAV/APE/CUE 能播、采样率跟随、信号路径可查、队列与模式可用、会话能恢复。** 这 6 条任何一条不达标则不发布。
